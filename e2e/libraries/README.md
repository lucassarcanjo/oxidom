# Real-world library compatibility: jsdom vs happy-dom vs oxidom

> Committed here: the summaries of the 2026-10-17 baseline. The large outputs (`results/libs.json` and `results/raw/`) are gitignored and
> regenerated by a run; the baseline copies stayed in oxidom-lab.

This study runs 41 smoke tests against 20 popular UI and network libraries. They are written the way app tests usually are: render, then interact with `@testing-library/user-event`, then assert with jest-dom. The suite runs under jsdom 30.1.3, happy-dom 21.0.3 and oxidom (this repo). Only `DOM_ENV` changes between runs. For every failure, the root cause was identified and verified.

**Results:** [`results/summary.md`](results/summary.md) is the readable version. [`results/libs.json`](results/libs.json) holds everything, including per-test rows, first errors, causes, census and raw run data. [`results/census.json`](results/census.json) is the static API census.

## Re-run

```sh
./run.sh                      # npm ci (first time), then run.mjs, census.mjs, aggregate.mjs
node run.mjs --doms=oxidom --modes=polyfills   # subset; then node aggregate.mjs needs all 9 runs present
DOM_ENV=happy-dom npx vitest run tests/radix.test.tsx   # one file, one DOM
```

`run.mjs` runs Vitest 9 times, one process at a time: {jsdom, happy-dom, oxidom} × {`polyfills`, `nopolyfills`, `diagnostics`}. Each run writes `results/raw/<mode>-<dom>.json` (Vitest JSON reporter) and `.log` (the default reporter without colour; the aggregator reads the "Unhandled Errors" section from it). Results are deterministic: two consecutive full runs gave identical totals and identical status for every library.

## Layout

| path | what |
|---|---|
| `package.json` | Exact versions. react 19.3.1, vitest 5.0.5, vite 8.3.4 and @testing-library/* match `e2e/react-app/`. The 20 libraries use the latest versions as of 2026-10-17. |
| `vitest.config.ts` | Picks the DOM with `DOM_ENV`, the same way `e2e/react-app/vitest.config.ts` does. oxidom is loaded by path from `../../oxidom/js/vitest-environment.js`. All three use the URL `http://localhost:3000/`. |
| `tests/setup.ts` | jest-dom, RTL cleanup and the **documented shims**. Each shim is installed only when the API is missing, and the code is identical for all DOMs. `LIBS_POLYFILLS=0` disables them. |
| `tests/*.test.tsx` | The library smoke tests. The first `describe` title is the library name, and the aggregator groups results by it. |
| `tests/_env-probe.test.ts` | Records which shims each DOM needed and whether each census API is available natively (`results/raw/probe-*.json`). |
| `diagnostics/facts.test.ts` | Root-cause facts per DOM, for example `NodeFilter` presence, Selection `rangeCount` after `collapse()`, whether `history.back()` fires `popstate`, and `document instanceof window.Document`. Output goes to `results/raw/diag-facts-*.json`. |
| `diagnostics/counterfactual.test.tsx` | Re-runs a failing scenario after shimming *only* the suspected API, to prove the cause. These shims are evidence only and `tests/` never uses them. |
| `apis.mjs` | The DOM API list used by the census: a regex for library code plus a runtime probe expression. |
| `census.mjs` | Static census: a regex search of each library's shipped JS and its dependency closure, excluding react and react-dom. It is crossed with native availability. |
| `causes.mjs` | The table of verified root causes. Every failing test and unhandled error is matched to it by DOM, file and error regex. Anything that does not match is listed under `unexplained`. |
| `aggregate.mjs` | Builds `results/libs.json` and `results/summary.md`. |

## Rules followed

- Tests stay DOM-agnostic. There are no environment checks in tests, and there are no retries.
- Shims are limited to what library docs or the Jest docs tell jsdom users to add: `matchMedia`, `ResizeObserver`, `scrollIntoView`, and `has/set/releasePointerCapture` (Radix). tabbable and focus-trap use `displayCheck: 'none'`, as their "Testing in JSDom" READMEs say. A second run with no shims measures what each DOM gives out of the box.
- Status per library: `pass` means every test passed with no unhandled error. `fail` means a test failed or the file failed to import. `error` means every assertion passed but Vitest reported an unhandled error or rejection, so the run exits 1.
- Nothing under `oxidom/` or `e2e/react-app/` was modified.
